How this works: The math path computes A = B_i + (W/J)(S - ln f_obj) + (W/J)(S - ln f_loc) exactly for each test probe, using the study list to derive B_i. The simulation runs N subjects, each walking the study list to build memory traces, then attempting retrieval at test with logistic noise. If both paths agree (within sampling error), the implementation is correct. A systematic discrepancy means a bug in one or the other.

Core Concepts
Fan effect
Retrieval slows and accuracy drops as the number of facts associated with an item increases.
Fan
The number of facts an item appears in. In ACT-R: Sji = S − ln(fan).
Fact
A sentence pairing an object and a location (e.g., "fox is in park"). The unit of study and the unit stored in memory as a chunk.
Item
Any object or location. The building blocks of facts.
Object / Location
The two roles in a fact. Object appears before "is in"; location after.
Identifier
A generated word (nonsense or noun) before it is assigned to a role. Once assigned, it becomes an item.
Experimental Design
Presentation
One appearance of a fact in the study list. A fact with 4 presentations appears four times during study.
Spacing / Lag
The interval between consecutive presentations of the same fact.
Probe
A single test stimulus presented during the test phase.
Target
A probe that was studied. Correct response: "yes."
Foil
A probe not studied, constructed by rearranging items from studied facts while maintaining fan. Correct response: "no."
Cell
A crossed condition: object fan × location fan (e.g., 2×3).
Crossed design
Object fan and location fan vary independently. Produces the full grid of cells.
Matched design
Both sides of every fact have the same fan. Only diagonal cells (1×1, 2×2, ...). Used by Schneider & Anderson (2012).
ACT-R Model
Activation (A)
Total activation of a chunk: A = Bi + Σj Wj · Sji.
Base-level activation (Bi)
Practice component: B = ln(Σ tk−d). Set to 0 when facts are overlearned.
Spreading activation
Fan component: (W/J)(S − ln(fan)) per source. Higher fan = weaker contribution.
Source
A retrieval cue. Object and location are the two sources (J = 2).
Recall-to-reject
Foil rejection: retrieve best-matching studied fact, detect mismatch, respond "no."
Guessing
When retrieval fails, guess at 50%. P(correct) = 0.5 + 0.5 × P(retrieve).
Parameters
W = 1.0
Total source activation.
S = 1.5
Maximum associative strength (at fan 1).
s = 0.42
Logistic noise scale.
τ = 0
Retrieval threshold.
J = 2
Number of sources.
d = 0.5
Decay exponent (fixed decay model).
Overview
This tool builds and simulates fan effect experiments in eight tabs. Tabs 1–4 form the main pipeline: generate identifiers, build trials, preview ACT-R predictions, and run simulations. Tabs 5–8 are support: code health analysis, test registry, this glossary, and this manual.
Tab 1: Items
Purpose: Generate identifiers (nonsense words, concrete nouns, or both) that will serve as objects and locations in the experiment.

Workflow:
1. Choose mode (nonsense, nouns, or both), count, and optional seed.
2. Set filters: length range, exclude regex (one pattern per line), dictionary flagging.
3. Click Generate. Results show each identifier with type, length, and token counts.
4. Click Send to Trials tab to pass identifiers directly to Tab 2 as input.

Outputs: CSV export, clipboard copy (all or clean only).
Tab 2: Trials
Purpose: Configure the experiment design, assign fan values to items, and generate study and test lists.

Workflow:
1. Set object and location fan values (number, spacing: linear or log).
2. Set items per fan and presentations per fan for each side.
3. Choose crossing (crossed or matched), foils per target, probe template.
4. Click Pre-run to see requirements without building (how many identifiers needed, fact-slot balance).
5. Load identifier CSVs (or use items from Tab 1), select the column to use.
6. Click Build Trials. Produces study list, test list, and 9 diagnostic charts.

Diagnostics (after Build):
• 7 verification checks: fan assignment, duplicates, foil overlap, target/foil ratio, presentation counts, Kruskal-Wallis on study and test serial position.
• 9 charts: probe counts by cell, presentations per fact, retention intervals, fan verification, foil cue sharing, study/test serial position strips, KW mean rank bars for study and test.

Outputs: study_list.csv, test_list.csv.
Tab 3: ACT-R Predictions
Purpose: Preview the pure spreading-activation prediction curve with B = 0 (Schneider & Anderson, 2012 paradigm).

Workflow:
1. Adjust W, S, s, τ parameters (defaults from Schneider & Anderson).
2. Fan values auto-read from Tab 2. Two charts: standard scale and log-log.
3. Click Reset to restore defaults.

Key insight: This tab assumes all facts are overlearned (B = 0). The fan effect comes entirely from spreading activation. Use Tab 4 to model the full ACT-R with practice history.
Tab 4: Simulate
Purpose: Run the full ACT-R model with base-level activation from the study history. Math predictions and Monte Carlo simulation, verified against each other.

Workflow:
1. Choose input source: from Trials tab (auto) or load CSVs.
2. Set retrieval parameters (W, S, s, τ, J).
3. Choose base-level model: B = 0 (overlearned), fixed decay, or Pavlik (2005).
4. If using decay: set d, sec/trial, gap.
5. Set N subjects and seed for Monte Carlo.
6. Click Run.

Outputs:
• Convergence check (math vs. simulation agreement).
• Cell-level summary table with B, spread, A, P(retrieve), P(correct) for math and sim.
• Probe-level detail table (click any row to see its study history).
• 4 charts: math vs. sim accuracy, base-level by fan, activation decomposition, P(retrieve) vs. P(correct) with guessing floor.
• CSV exports: cell summary, probe detail, parameters.
Tab 5: Health
Purpose: Code complexity analysis using cyclomatic complexity (McCabe, 1976; NASA SATC).

Click Analyze to scan every JS function. Reports CC, line count, and status (OK / WARNING / DANGER). Functions exceeding the NIST 235 ceiling (CC ≥ 15) or the NASA SATC combined risk threshold (CC ≥ 10 + lines ≥ 50) are flagged for refactoring.
Tab 6: Tests
Purpose: Registry of unit test files with coverage and status.

60 tests done (30 trial generator, 30 simulation), ~40 planned. To generate Python test files: upload this HTML to a Claude conversation and ask it to produce matching tests from the JS source.
Recommended First Run
1. Tab 1: Generate 12 identifiers (mode: nouns, category: mixed).
2. Tab 1: Click "Send to Trials tab."
3. Tab 2: Set fan values 1,2,3 (linear). Items per fan: 4. Presentations per fan: 8,4,2. Crossing: crossed.
4. Tab 2: Click Build Trials. Check all 7 diagnostics pass. Review the 9 charts.
5. Tab 3: Inspect the ACT-R prediction curve.
6. Tab 4: Set model to B = 0. Click Run. Verify convergence passes. Compare math vs. sim chart.
7. Tab 4: Switch model to Fixed decay. Set sec/trial = 5, gap = 30. Re-run. Note how B shifts the curve.
